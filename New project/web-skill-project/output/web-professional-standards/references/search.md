# Search, route identity and navigation

Start with a map of public, private, moved and intentionally absent destinations. Confirm the expected content for each primary route, who owns it and which language is actually presented. Use crawlable descriptive links and meaningful document titles, headings and language declarations.

For a public page, compare the published response status, final URL, page-specific visible content, canonical target and effective robots policy with the intent. Inspect response headers as well as markup where relevant. A generic shell can return 200 for a missing destination. Robots.txt controls crawling and cannot on its own guarantee removal from the index. A crawler generally needs access to see a noindex directive. Private information requires access control.

For alternate languages, link genuine equivalents, check language and regional codes, self and return references where applicable, and allow visitors to reach the intended version. Add sitemap and structured data only for eligible, maintained URLs and accurate visible claims. Confirm contact links and anchor targets in the deployed context. Document any external destination the environment could not reach.

For a migration, map valuable old URLs to the corresponding new content. Check a representative moved, unchanged and removed URL, redirects, final content and internal links. Confirm canonical, indexing policy, sitemap and localization after cutover. Define the owner, monitoring window and correction or rollback path. Indexing and ranking outcomes require separate observation over time. [Google site moves](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes)
