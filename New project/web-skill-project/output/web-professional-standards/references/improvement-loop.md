# Improvement loop

Open on a confirmed defect, concrete feedback, regression or an explicit learning request. Capture what the person observed, where it affected the task and what is still unknown. Separate the observation from a proposed cause. Fix or document the project issue within the authorized scope.

1. **Find the missed decision.** Compare expected and actual behavior, relevant evidence and the earliest assumption that matters. Decide whether this is a local implementation error, brand preference, platform change or transferable omission. A single preference can remain in the project.
2. **Prepare a candidate.** Record a generalized trigger, consequence, evidence or unknown cause, missed question, prevention, boundary and a regression check. Remove client identities, secrets, personally identifiable data, raw code and business material. Merge equivalent candidates. If the user has approved a shared maintenance location, append the sanitized record to `SKILL_IMPROVEMENT_CANDIDATES.md` there, outside the client repo and distributed skill. Otherwise return a copyable candidate.
3. **Propose the exact durable change.** Name the current version and file, show the diff or replacement text, a case it helps, a counterexample where it would overreach, and its additional reading cost. Improve the reasoning question if the method failed. Add a catalog entry only if recognizing the mechanism changes a decision. Choose a reference when most activations do not need the detail.
4. **Wait for explicit approval of that change.** Permission to save a candidate covers only the candidate. After approval, retain a previous revision, apply a versioned edit, and record the rollback action. Check the original regression, a different transferable case, the counterexample and trigger behavior. Record the evidence and limits. An untested amendment stays pending validation. Retire a rule when its cause has disappeared.
